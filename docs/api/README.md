# HTTP/SSE API

The v1 API is served under `/api/v1/` and only binds to loopback.

Authentication: `Authorization: Bearer <token>`. The token is generated by `cofer-u-pass setup` and stored in the configured token file.

Primary resources:

- `POST /api/v1/runs`
- `GET /api/v1/runs/{run_id}`
- `GET /api/v1/runs/{run_id}/status`
- `GET /api/v1/runs/{run_id}/events` (SSE)
- `POST /api/v1/runs/{run_id}/cancel`
- `POST /api/v1/runs/{run_id}/resume`
- `POST /api/v1/runs/{run_id}/resolve-outcome`
- `GET /api/v1/runs/{run_id}/result`
- `GET /api/v1/runs/{run_id}/artifacts`
- `GET /api/v1/runs/{run_id}/diagnostics`

SSE clients reconnect with `Last-Event-ID`; the server resolves that persisted event and emits only subsequent events in monotonic sequence order.

FastAPI generates OpenAPI from the shared Pydantic request/domain contracts at runtime at `/openapi.json`.
