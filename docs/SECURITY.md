# Security Policy

## Trust model

Cofer U Pass v1 is a local, single-operating-system-user application. The engine, installed adapters, approved protocols, and installed hooks are trusted local components. Provider DOM, generated text, downloaded files, and web content are untrusted data.

The product does not automate passwords, MFA, CAPTCHA, verification codes, or consent. Authentication occurs manually in a visible Playwright-managed Chromium profile.

## Local API

The HTTP API is hard-restricted to loopback (`127.0.0.1`, `::1`, or `localhost`) and requires a random bearer token stored under the local data root. The token is never accepted in URLs. Remote publication, tunnels, TLS termination, and multi-user authentication are outside v1.

## Browser profiles

Each profile has a dedicated persistent Chromium directory. Cookies and session storage remain there and are never copied into SQLite or diagnostic packages. Linux profile directories are created with mode `0700`. Windows relies on the current user's filesystem ACLs and the operating system's profile protection.

## External-effect safety

Actions such as message submission and file upload are journaled separately from run creation. If an interruption occurs after an external effect may have happened but before its postcondition is confirmed, the action and run become `outcome_unknown`. Automatic retry is forbidden until a human explicitly resolves the uncertain effect.

## Hooks

Hooks are trusted local Python code. They execute in a separate process with a reduced environment and bounded input/output, but this is not a hostile-code sandbox. Installing a hook is equivalent to trusting local code execution.

## Diagnostics

Diagnostic packages are local and never uploaded automatically. Sensitive-key redaction removes common token/password/session fields and bearer values. Packages intentionally exclude browser profiles, cookies, session storage, API tokens, passwords, MFA data, and unrelated conversations.

## Reporting

Do not attach browser profile directories, API token files, cookies, or authentication material to bug reports. Prefer a sanitized package generated by `cofer-u-pass doctor --run-id <RUN_ID>` and inspect it with `cofer-u-pass diagnostics inventory <PACKAGE_DIR>` before sharing.
